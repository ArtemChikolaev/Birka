# Design

The mockups of the first version, drawn in October 2026 before the app had
its screens. They set the direction; the exact values live in the design
tokens ([ADR 0007](../adr/0007-design-tokens.md)). When the app and a mockup
disagree, the app and the tokens win, and the mockup gets updated or
retired. Every name and amount in them is made up.

Each screen is a PNG at twice the size of a 390 × 844 phone screen.

## Design system

The design system lives on claude.ai as a Design System artifact:
[Birka](https://claude.ai/artifact/4QTZ9M8s2RqeTRNuNjHLuV). It holds the
tokens, the type with the fonts of the site, the components of the web kit
with live previews and guidelines, the icons, the brand and these mockups.
Its source is [system/](system/), laid out as the artifact's `project/`
folder, so that nothing of the design lives only in an account:

| In `system/` | Comes from |
|---|---|
| `tokens.json` | generated by `make tokens` from the design tokens; `make check-tokens` keeps it in step |
| `README.md` | the brand book, written by hand |
| `components/bundle.css` | the `@css` rules of the web kit, copied by hand |
| `components/<Name>/` | a static preview and the guidelines of each component |
| `design-system.json` | the index of the artifact, with the ids of the uploaded icons, brand art and mockups |

The fonts, icons, brand art and mockups are not copied: they are published
from `packages/design/jaspr/lib/fonts/`, `packages/design/flutter/icons/`,
`packages/design/brand/` and `mockups/`.

## Design canvas

The boards of every feature, for the phone and for the site, are on the
Claude Design canvas
[Birka · Ночь](https://claude.ai/artifact/HWbDNV7NtL5RoBHrLiXqhf). Its source
is [canvas/](canvas/), laid out as the canvas's `project/` folder: the index
`canvas.json` and one `.dc.html` per board. The first canvas lived in an
account that is gone; [canvas/README.md](canvas/README.md) says what was
recovered and what was lost.

Design work done on claude.ai, in Claude Design or in an artifact, comes back
into this folder in the same pull request: new mockups as PNGs into
`mockups/`, changes of the system into `system/`, new and changed boards into
`canvas/`. When a token or a component
of the kit changes, update `system/` and publish it again.

## Design language

| Element | In the mockups |
|---|---|
| Base | black; emerald only for accents: the main button, the selected tab, income, progress |
| Surfaces | Liquid Glass: the backdrop blurred with its colors made richer, a faint white gradient fill, a hairline border and a light line along the top edge |
| Glow | a faint emerald glow in the top left and bottom right corners and on the left edge of every screen |
| Type | Manrope ExtraBold for titles and amounts, Inter for the rest; amounts in tabular figures; section labels in spaced capitals |
| Navigation | a floating glass bar centered at the bottom, with a bubble under the selected tab and the add button in the middle |
| Categories | a color each: green, amber, sky, violet, rose, orange, cyan |
| Accounts | cards with abstract art in the color of the account |

### Operations search across months

Start typing in Operations, then enable All months to include older matches.
The selected transaction type still applies. The totals describe the matches,
and dates from earlier years include the year. Clearing the query or turning
off All months returns to the month being viewed. Search opened from an Ask
answer stays within the answer's operations. Long results open 30 matching
days at a time, keeping every operation of the last visible day together.
The count and amounts cover all matches. In the mockup, search for `обед`
across months to try the longer list.

### Telegram codes for the Birka account

In the [interactive prototype](mockups/optional-account.html#telegram), choose
Telegram, enter a phone number with its country code, and allow Birka to share
that number with Telegram for code delivery. When enabled on the service, Telegram Gateway delivers a
Birka verification code to the Telegram account registered to that number.
[Gateway integration and account linking](../adr/0036-telegram-gateway.md)

- **First sign-in.** After a new number is verified, choose to create an
  account or sign in to an existing email account. A known number opens the
  linked profile directly.
- **One account, two methods.** Sign in with the existing method, add the
  second from the profile, and verify its code. A method already in use
  stays with its owner. The profile lists the email and masked number.
- **Delivery and recovery.** A code expires in ten minutes. Resend becomes
  available after one minute and replaces the previous code. The user can edit
  the number, switch to email or cancel linking. Email can recover an existing
  identity when the email belongs to that identity.
- **Local ledger.** Selecting a different device switches its local counts
  and session. Signing in from a fresh device opens the same profile with
  an empty local ledger. Guest access and the existing backup path remain available.

To try linking, select **Почта** and use the prefilled synthetic address.
The example code appears beneath the form. In the profile, choose
**Привязать Telegram** and verify the second code. Switch to **Новое устройство**
to try the linked number. **Параметры макета** can simulate a delivery failure.
Reloading the HTML resets both devices and all sample identities.

[Phone preview](mockups/35-telegram-sign-in-phone.png) ·
[Desktop profile with both sign-in methods](mockups/36-telegram-profile-web.png)

### Finding a category

In **More → Categories**, search within expenses or income by any part of a
name. A matching parent shows its active children. A matching child keeps
its parent above it. The archive lists its own name matches separately.
Clearing the field restores the directory in its original order. Switching
between expenses and income starts a fresh search. Opening a category to
edit it and returning keeps the query.

### Capital by currency

On **Accounts**, expand **By currency** beneath the capital total to see the
net balance and account count for each original currency, in the order of
the first counted account. Only active accounts included in capital contribute.
Zero and negative balances keep their place. The breakdown is available for
multiple currencies and for a single currency converted into a different
display currency. If a currency subtotal exceeds the supported money range,
the breakdown shows the applicable bound with < or >. The rows work offline
and respect hidden amounts.

### Regular payment calendar

In **Regular payments**, the calendar opens on 30 days. Choose 7 or 90 days
to see every occurrence in that window, including today and the last date
shown. Payments awaiting confirmation appear above the calendar. The full
directory remains below it. A [busy calendar](mockups/schedule-calendar.html#busy) shows 20 occurrences at a time.
Opening a payment and returning keeps the chosen period and visible rows.
